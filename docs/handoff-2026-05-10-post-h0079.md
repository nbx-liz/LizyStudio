### Wave 1.1 Proposal の論点（事前検討）

ユーザに確認が必要な設計判断:

**Q1**: `option_sets.objective` の master を **LizyML `objective_choices()` の全 canonical（9/3/2）** にするか、**LizyML `_DEFAULT_TUNE_OBJECTIVES` の conservative subset**（`gamma`/`poisson`/`tweedie`/`mape` 除外）にするか
- 全 canonical: ユーザに最大の選択肢、ただし `gamma` 等は target 分布制約あり
- conservative: tune-safe、ただし「LightGBM が許す全 objective」を見せたいユーザには不足

**Q2**: `option_sets.metric` の表示で `metric_choices(task)["feval"]` の項目に「Custom (slow)」バッジを付けるか
- バッジ有り: ユーザが学習速度を意識できる
- バッジ無し: UI シンプル化

**Q3**: `option_sets.model_metric` を撤廃するか保持するか
- 撤廃: SSOT 一本化（`option_sets.metric` のみ残す）、ただし LightGBM 生名の表示が消える
- 保持: ユーザが LightGBM 生名で指定できる、ただし Studio 側で aliases 整理が必要
